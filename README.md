## 핵심 구현 및 개발 포인트
- **MyBatis 동적 쿼리를 활용한 다중 조건 복합 필터링 및 검색 시스템 구축**
    - 사용자 편의성을 위해 단일 검색(시약명, CAS 번호) 및 다중 필터(승인 타입, 내용, 결재 상태) 조건을 조합할 수 있는 기능을 구현했습니다.
    - MyBatis의 <if>, <choose> 태그를 적극 활용하여, 화면에서 유입되는 조건에 따라 SQL 구문이 가변적으로 생성되도록 동적 쿼리를 최적화함으로써 불필요한 데이터 조회를 줄이고 정확한 타겟 데이터를 추출했습니다.
- **결재 상태 및 재고 연동 프로세스의 데이터 무결성 확보**
    - 시약 사용 요청에 대한 승인/반려 워크플로우를 구현하며, 비즈니스 로직의 신뢰성을 확보했습니다.
    - '사용 승인' 이벤트 발생 시 결재 상태 변경(Update)과 시약 재고 차감(Update)이 유기적으로 이루어지도록 프로세스를 설계하였고, 화면(Modal) 단과의 싱크를 맞춰 안정적인 관리 흐름을 완성했습니다.

## 트러블 슈팅
- **[현상]** 결재 승인 처리 시 상태 값은 변경되나 시약 재고 데이터가 차감되지 않거나, 일부 원장 테이블에 데이터가 누락되는 현상 발생함 (데이터 불일치 문제)
- **[원인]** 승인/반려 처리 로직과 시약 재고 조절 로직이 함께 성공하거나 함께 취소되도록 하나의 Transaction으로 묶여 있지 않아, 중간에 예외가 발생했을 때 앞서 처리된 내용만 저장되고 이후 처리는 누락되는 현상이 발생함
- **[해결]** Spring Boot 환경에서 서비스 레이어에 @Transactional 어노테이션을 도입하여 여러 테이블에 걸친 CUD 작업이 모두 성공(Commit)하거나 실패 시 모두 이전 상태로 되돌아가는(Rollback) 구조로 변경. 또한 승인과 반려의 데이터 처리 시점을 명확히 분리하여 쿼리 실행 순서를 안정화함
- **[배운점]** 금융, 전산, 결재 시스템처럼 한 번의 요청으로 여러 데이터베이스 테이블이 함께 변경되는 경우, 일부 작업만 반영되지 않도록 트랜잭션으로 전체 작업을 하나의 처리 흐름으로 관리하는 것이 안정적인 시스템을 만드는 데 중요하다는 점을 배웠습니다.
